## 1. Overview & Purpose

In legal and investigative contexts, software cannot unilaterally claim statutory certification. However, digital forensic evidence examination must strictly comply with established forensic principles:
1. **Identifiability:** Clear recording of evidence provenance, file size, and container type.
2. **Immutability:** Cryptographic SHA-256 verification before and after analysis.
3. **Reproducibility:** Documented signal processing parameters, software versions, and mathematical models.
4. **Transparency & Epistemic Caution:** Explicit statement of technical limitations and non-dogmatic probabilistic conclusions.

## 2. Formal 10-Section Structure

Every examination report generated by `create_forensic_report` conforms to the following 10-section structure:

| Section | Title | Primary Contents |
|---|---|---|
| **1** | **Case Information** | Case Reference ID, Unique Evidence Tracking ID, Examiner Name, Timestamp (UTC), Examination Status (`COMPLETED`, `INDETERMINATE`). |
| **2** | **Evidence Information & Chain of Custody** | Exhibit Filename, SHA-256 Digest, Container Format, File Size in bytes, Duration, Sampling Rate, Channel Count, Immutability Confirmation. |
| **3** | **Examination Methodology** | Audio downmixing to 16 kHz mono floating-point, peak normalization, 26 standardized features (MFCC 1-20 with Slaney 128-band dB scaling, Centroid, Rolloff, Bandwidth, ZCR, RMS, Chroma). |
| **4** | **Acoustic Quality & Feature Distribution** | Estimated SNR (dB), Digital Clipping Ratio, Silence Percentage, and Domain Validation ($z$-score status vs empirical bounds). |
| **5** | **Machine Learning Results** | Primary Finding (`GENUINE` / `SYNTHETIC` / `INDETERMINATE`), Decision Confidence, Decision Score, Calibrated Posterior Probabilities, Multi-Model Comparison Table. |
| **6** | **Visual Evidence & Spectrogram Analysis** | High-resolution multi-panel spectrogram overview, STFT, Mel, and MFCC heatmap file references. |
| **7** | **Evidentiary Limitations & Technical Boundaries** | Codec compression vulnerabilities (MP3/Opus), Telephony bandpass filtering (G.711 < 3.4 kHz), Noise sensitivity (< 20 dB SNR), and Cross-speaker generalization bounds. |
| **8** | **Forensic Conclusion** | Cautious scientific assessment statement adhering to SWGDE phrasing standards. |
| **9** | **Cryptographic Integrity Statement** | Certification of read-only processing, bitstream hash immutability, and absence of evidence alteration. |
| **10** | **Technical References & Software Environment** | References to ISO/IEC 27037:2012, SWGDE, Python 3.14.3, NumPy 2.2.3, Scikit-Learn 1.6.1, SoundFile 0.13.1. |
