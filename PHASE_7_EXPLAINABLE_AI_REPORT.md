## 1. Executive Summary

Phase 7.1 establishes a mathematically rigorous, dependency-minimized Explainable AI (XAI) framework tailored specifically for forensic audio investigations. Because Windows Defender Application Control (WDAC) blocks external C-extension packages like `shap` and `lime` in this execution environment, a clean pure-Python/NumPy implementation was engineered.

The XAI framework provides two complementary levels of explanation:
1. **Global Model Interpretability:** Intrinsic coefficient analysis for linear baselines (Logistic Regression) and Gini feature importances for tree ensembles (Random Forest).
2. **Local Instance-Level Attribution:** Feature occlusion sensitivity and pure-Python Monte Carlo Shapley sampling across 26 canonical MFCC acoustic statistics.

## 2. Mathematical Formulations

### 2.1 Feature Occlusion Sensitivity
For an input feature vector $\mathbf{x} = (x_1, x_2, \dots, x_{26}) \in \mathbb{R}^{26}$, the model outputs a probability of synthesis:
$$P(\text{Synthetic} \mid \mathbf{x}) = f(\mathbf{x})$$

The occlusion impact of feature $j$ is computed by replacing $x_j$ with a neutral baseline reference $r_j = 0$ (or population mean $\mu_j$):
$$\mathbf{x}_{\setminus j} = (x_1, \dots, x_{j-1}, r_j, x_{j+1}, \dots, x_{26})$$
$$\Delta P_j = f(\mathbf{x}) - f(\mathbf{x}_{\setminus j})$$

- $\Delta P_j > +0.005$: Feature $j$ pushes the model toward **SYNTHETIC** (`TOWARD_SYNTHETIC`).
- $\Delta P_j < -0.005$: Feature $j$ pushes the model toward **GENUINE** (`TOWARD_GENUINE`).
- $|\Delta P_j| \le 0.005$: Neutral influence (`NEUTRAL`).

### 2.2 Pure-Python Monte Carlo Shapley Estimation
To capture non-linear feature interactions without external library bloat, Shapley values $\phi_j$ are estimated via Monte Carlo permutation sampling:
$$\phi_j(f) = \frac{1}{M} \sum_{m=1}^M \left[ f(S_m \cup \{j\}) - f(S_m) \right]$$
where $M=35$ random permutations are drawn, and $S_m$ represents the subset of features preceding feature $j$ in permutation $m$. This yields an unbiased estimate of the cooperative game-theoretic attribution of each acoustic descriptor.

## 3. Acoustic Feature Grouping

Features are categorized into functional acoustic dimensions to assist investigators without requiring deep signal-processing backgrounds:

| Group ID | Included Features | Forensic Acoustic Significance |
| :--- | :--- | :--- |
| **MEAN:LOW_BAND** | `mfcc_1_mean` to `mfcc_4_mean` | Vocal tract fundamental resonance, formant energy balance, chest resonance. |

| **STD:HIGH_BAND** | `mfcc_9_std` to `mfcc_13_std` | Spectral flux variability, vocoder phase jitter, background room coloration. |

## 4. Input Validation & Schema Guard

To guarantee court admissibility and system stability, `explain_prediction()` enforces rigorous validation:
1. **Schema Check:** Verifies feature dimensionality against `models/feature_names.json`. Vectors not matching exactly 26 dimensions are rejected with `ValueError: Feature schema mismatch`.
2. **Quality & Range Check:** Audio with SNR < 10 dB or clipping ratio > 0.05 triggers quality warnings before attribution calculation.
3. **Database Audit Logging:** Every XAI execution creates an immutable `AnalysisRun` record in SQLite (`analysis_runs`), storing the input SHA-256 hash, parameters, software versions, and generated findings.
